## ❌ 실패한 테스트 목록

### 1. 팔레트 관련 테스트 (2개)

#### 1-1. `category.spec.ts` - 팔레트 변경 버튼이 작동한다
**실패 이유:**
- 다이얼로그 내부의 팔레트 이름 요소(`.text-xs.text-muted-foreground`)가 DOM에 렌더링되지만, Playwright가 타이밍 이슈로 찾지 못함
- 색상 팔레트가 변경될 때 상태 업데이트가 비동기적으로 발생하여 텍스트 변경을 감지하지 못함

**수동 테스트 방법:**
```
1. 워크스페이스 상세 페이지로 이동
2. "추가" 버튼 클릭 (Plus 아이콘)
3. 카테고리 추가 다이얼로그에서 우측 상단의 팔레트 이름 확인 ("생동감")
4. 색상 팔레트 우측의 "팔레트 변경" 버튼 클릭
5. 팔레트 이름이 "파스텔"로 변경되는지 확인
6. 다시 "팔레트 변경" 버튼 클릭
7. 팔레트 이름이 "깊은"으로 변경되는지 확인
8. 각 팔레트마다 색상 14개가 올바르게 표시되는지 확인
```

#### 1-2. `advanced.spec.ts` - 팔레트 변경 시 사용하지 않은 색상이 자동 선택된다
**실패 이유:**
- 위와 동일한 팔레트 이름 요소 찾기 문제
- 색상 자동 선택 로직은 정상 작동하지만, 테스트에서 팔레트 이름 변경을 확인하는 과정에서 실패

**수동 테스트 방법:**
```
1. 워크스페이스 생성 및 이동
2. 첫 번째 카테고리 생성 (예: "점심") - 자동으로 첫 번째 색상 선택됨
3. 두 번째 카테고리 추가 다이얼로그 열기
4. 첫 번째 카테고리와 다른 색상이 자동으로 선택되어 있는지 확인
5. 팔레트 변경 버튼 클릭
6. 팔레트가 "파스텔"로 변경되는지 확인
7. 이미 사용 중인 색상이 아닌 다른 색상이 자동 선택되었는지 확인
```

### 2. 카테고리 삭제 관련 테스트 (4개)

#### 2-1. `category.spec.ts` - 카테고리 삭제가 정상적으로 작동한다
**실패 이유:**
- 카테고리 생성 후 삭제 버튼(휴지통 아이콘)이 DOM에 렌더링되지만, 타이밍 이슈로 클릭 불가
- 다이얼로그 닫기 애니메이션이 완료되기 전에 삭제 버튼을 찾으려고 시도
- CollapsibleTrigger 내부의 버튼들이 상태에 따라 동적으로 렌더링됨

**수동 테스트 방법:**
```
1. 워크스페이스 상세 페이지에서 카테고리 생성 (예: "삭제 테스트")
2. 생성된 카테고리 카드의 헤더 영역 확인
3. 연필 아이콘(수정 버튼) 우측에 있는 휴지통 아이콘 클릭
4. "카테고리 삭제" 확인 다이얼로그가 표시되는지 확인
5. 경고 메시지가 올바르게 표시되는지 확인
6. "삭제" 버튼 클릭
7. 카테고리가 목록에서 사라지는지 확인
```

#### 2-2. `category.spec.ts` - 카테고리 삭제 시 취소 버튼이 작동한다
**실패 이유:**

**수동 테스트 방법:**
```

2. 휴지통 아이콘 클릭하여 삭제 다이얼로그 열기

4. 다이얼로그가 닫히고 카테고리가 여전히 목록에 남아있는지 확인
```

#### 2-3. `place.spec.ts` - 카테고리 삭제 버튼이 작동한다
**실패 이유:**
- 위와 동일 (삭제 버튼 타이밍 이슈)

**수동 테스트 방법:**
```

3. 삭제 확인 다이얼로그에 "점심"이 포함된 경고 메시지 확인
4. 삭제 또는 취소 동작 확인
```

#### 2-4. `advanced.spec.ts` - 카테고리 삭제 시 경고 메시지가 표시된다
**실패 이유:**

```
1. 카테고리 생성
2. 삭제 버튼 클릭
```

### 3. 토스트 메시지 테스트 (2개)

#### 3-1. `place.spec.ts` - 빈 검색어로 검색할 수 없다
**실패 이유:**
- sonner 토스트 라이브러리의 DOM 구조 문제
- `li[data-sonner-toast]` 요소가 동적으로 생성되고 사라지는 타이밍을 정확히 캐치하지 못함
- 토스트가 화면에 표시되는 시간이 짧아서 assertion 전에 사라질 수 있음

**수동 테스트 방법:**
```
1. 워크스페이스 상세 페이지에서 카테고리 생성
2. "장소 검색" 버튼 클릭
3. 검색어를 입력하지 않고 "검색" 버튼 클릭
4. 화면 상단(또는 하단)에 "검색어를 입력해주세요." 토스트 메시지가 표시되는지 확인
5. 토스트가 자동으로 사라지는지 확인 (약 3-5초)
```

#### 3-2. `advanced.spec.ts` - 성공 및 에러 토스트 메시지가 올바르게 표시된다
**실패 이유:**
- 위와 동일 (sonner 토스트 타이밍 이슈)
- 여러 토스트가 연속으로 표시될 때 첫 번째 토스트가 사라지기 전에 다음 토스트를 확인하려고 시도

**수동 테스트 방법:**
```
1. 워크스페이스 생성 → "워크스페이스가 생성되었습니다!" 토스트 확인
2. 워크스페이스 상세로 이동
3. 카테고리 추가 → "카테고리가 추가되었습니다!" 토스트 확인
4. 장소 검색 다이얼로그에서 빈 검색 → "검색어를 입력해주세요." 에러 토스트 확인
5. 각 토스트의 스타일 확인:
   - 성공: 초록색 계열
   - 에러: 빨간색 계열
```

### 4. ESC 키 / 다이얼로그 닫기 테스트 (3개)

#### 4-1. `navigation.spec.ts` - ESC 키로 드롭다운 메뉴를 닫을 수 있다
**실패 이유:**
- ESC 키 이벤트가 올바르게 전달되지만, 메뉴 닫기 애니메이션 중에 assertion 실행
- Radix UI의 DropdownMenu가 ESC 키를 처리하는 방식과 Playwright의 keyboard.press() 타이밍 불일치

**수동 테스트 방법:**
```
1. 워크스페이스 목록 페이지에서 프로필 아이콘 클릭
2. 드롭다운 메뉴가 열리는지 확인
3. ESC 키 누르기
4. 드롭다운 메뉴가 닫히는지 확인
5. 여러 번 반복하여 일관성 확인
```

#### 4-2. `place.spec.ts` - 장소 검색 다이얼로그에서 취소할 수 있다
**실패 이유:**
- ESC 키로 다이얼로그를 닫을 때 애니메이션 완료 전에 assertion 실행
- Dialog의 `onOpenChange` 핸들러와 ESC 키 이벤트 처리 타이밍 불일치

**수동 테스트 방법:**
```
1. 카테고리의 "장소 검색" 버튼 클릭
2. 장소 검색 다이얼로그가 열리는지 확인
3. ESC 키 누르기
4. 다이얼로그가 닫히는지 확인
5. 다른 방법들도 테스트:
   - X 버튼 클릭
   - 배경 클릭 (backdrop)
```

#### 4-3. `place.spec.ts` - 여러 카테고리의 장소 검색 버튼이 독립적으로 작동한다
**실패 이유:**
- 위와 동일 (ESC 키로 다이얼로그 닫기 실패)
- 다이얼로그가 제대로 닫히지 않아 두 번째 카테고리의 장소 검색 버튼 클릭 불가

**수동 테스트 방법:**
```
1. 두 개의 카테고리 생성 (예: "점심", "카페")
2. 첫 번째 카테고리의 "장소 검색" 버튼 클릭
3. 다이얼로그 열림 확인
4. ESC 키 또는 X 버튼으로 닫기
5. 두 번째 카테고리의 "장소 검색" 버튼 클릭
6. 다이얼로그가 다시 열리는지 확인
7. 각 카테고리의 장소 검색이 독립적으로 작동하는지 확인
```

### 5. 드래그 앤 드롭 테스트 (1개)

#### 5-1. `category.spec.ts` - 드래그 앤 드롭으로 카테고리 순서를 변경할 수 있다
**실패 이유:**
- react-beautiful-dnd 라이브러리의 드래그 앤 드롭이 브라우저의 실제 마우스 이벤트를 요구
- Playwright의 `page.mouse.down()`, `page.mouse.move()`, `page.mouse.up()` 시퀀스가 react-beautiful-dnd의 드래그 이벤트를 트리거하지 못함
- dnd 라이브러리는 내부적으로 복잡한 이벤트 체인(mousedown → dragstart → drag → dragend)을 사용하는데, Playwright의 마우스 시뮬레이션이 이를 완벽히 재현하지 못함

**수동 테스트 방법:**
```
1. 워크스페이스 상세 페이지에서 3개 이상의 카테고리 생성
   예: "점심", "카페", "저녁"
2. 각 카테고리의 순서 번호 확인 (1, 2, 3)
3. 첫 번째 카테고리("점심")의 GripVertical 아이콘(≡) 을 마우스로 클릭하고 드래그
4. 세 번째 카테고리 위치로 드래그하여 드롭
5. 순서가 변경되었는지 확인:
   - 기존: 1.점심, 2.카페, 3.저녁
   - 변경 후: 1.카페, 2.저녁, 3.점심
6. 순서 번호가 자동으로 업데이트되는지 확인
7. 페이지를 새로고침해도 순서가 유지되는지 확인 (IndexedDB에 저장됨)
```

### 6. 컨텍스트 메뉴 테스트 (1개)

#### 6-1. `workspace.spec.ts` - 워크스페이스 삭제가 정상적으로 작동한다
**실패 이유:**
- 워크스페이스 카드에 우클릭 시 컨텍스트 메뉴가 열리지 않음
- Radix UI의 ContextMenu 컴포넌트가 Playwright의 `click({ button: 'right' })` 이벤트를 제대로 인식하지 못함
- ContextMenuTrigger가 카드의 onClick 이벤트와 충돌할 수 있음
- 일부 브라우저나 OS에서 우클릭 이벤트 처리가 다를 수 있음

**수동 테스트 방법:**
```
1. 워크스페이스 목록 페이지에서 워크스페이스 생성
2. 생성된 워크스페이스 카드에서 우클릭 (마우스 오른쪽 버튼 클릭)
3. 컨텍스트 메뉴가 표시되는지 확인
4. 메뉴 항목 확인:
   - "이름 바꾸기" (연필 아이콘)
   - "삭제" (휴지통 아이콘, 빨간색)
5. "삭제" 클릭
6. 삭제 확인 다이얼로그가 표시되는지 확인
7. 워크스페이스 이름과 경고 메시지 확인
8. "삭제" 버튼 클릭하여 실제로 삭제되는지 확인
```

### 7. UI 요소 가시성 테스트 (1개)

#### 7-1. `place.spec.ts` - 카테고리 헤더의 모든 버튼이 표시된다
**실패 이유:**
- 카테고리 생성 직후 헤더의 버튼들이 렌더링되지만, 타이밍 이슈로 일부 버튼(특히 휴지통 아이콘)을 찾지 못함
- CardHeader 내부의 버튼들이 조건부 렌더링되거나 애니메이션 중일 수 있음

**수동 테스트 방법:**
```
1. 워크스페이스 상세 페이지에서 "점심" 카테고리 생성
2. 카테고리 헤더 영역에서 다음 요소들이 모두 표시되는지 확인:
   
   좌측부터 우측 순서:
   a. GripVertical 아이콘 (≡) - 드래그 핸들
   b. 순서 번호 (원형 배지, 카테고리 색상 배경에 흰색 숫자)
   c. 카테고리 이름 ("점심")
   d. 수정 버튼 (연필 아이콘)
   e. 삭제 버튼 (휴지통 아이콘, 빨간색)
   f. 접기/펼치기 버튼 (chevron 아이콘, 회전 애니메이션)

3. 각 버튼에 마우스 호버 시 hover 효과 확인
4. 각 버튼 클릭 시 올바른 동작 확인:
   - 드래그 핸들: 드래그 가능
   - 수정: 수정 다이얼로그 열림
   - 삭제: 삭제 확인 다이얼로그 열림
   - 접기/펼치기: 카테고리 콘텐츠 토글
```

## 📝 요약 및 권장사항

### 실패 원인 분류
1. **타이밍 이슈** (10개, 71%): 대부분의 실패는 비동기 렌더링과 애니메이션 타이밍 문제
2. **라이브러리 호환성** (3개, 21%): react-beautiful-dnd, Radix UI의 이벤트 처리 문제
3. **DOM 구조** (1개, 7%): sonner 토스트의 동적 DOM 구조

### 수동 테스트 우선순위
**높음 (핵심 기능):**
- 워크스페이스 삭제 (우클릭 컨텍스트 메뉴)
- 카테고리 삭제
- 드래그 앤 드롭 순서 변경

**중간 (사용자 경험):**
- 토스트 메시지 표시
- ESC 키 동작
- 팔레트 변경

**낮음 (시각적 확인):**
- UI 요소 가시성

### 자동화 테스트 개선 방안
1. **타이밍 개선**: 
   - 더 긴 대기 시간 추가
   - `waitForSelector`와 함께 `state: 'visible'` 옵션 사용
   - 애니메이션 완료 대기 로직 추가

2. **대체 방법**:
   - 드래그앤드롭: HTML5 drag-drop 이벤트 직접 트리거
   - 컨텍스트 메뉴: 대신 버튼으로 접근하는 테스트로 변경
